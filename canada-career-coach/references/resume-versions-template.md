# Resume Versions Template

A **resume version** (also called a track) is a resume aimed at one role
family. Sending a single resume to every role usually dilutes the evidence;
two to four versions is a workable range. The coach recommends a version per
job posting, so each needs a clear definition.

## How to define a version

| Field | What to write |
|---|---|
| Name | A neutral label, such as "IT support / help desk", "Business or data analysis", "Project coordination" |
| File | Filename of the resume version |
| Target roles | Job titles it is meant for |
| Framing | What the top third of the page emphasizes (troubleshooting and customer service, analysis and reporting, coordination and stakeholder work, and so on) |
| Lead evidence | The 3–4 achievements that come first |
| Vocabulary | Terms this version uses on purpose |
| Not claimed | Things this version deliberately does not claim, even if the posting asks |

## How the coach uses versions

1. Extract the posting's keywords and seniority signals.
2. Score each version by overlap and by whether the lead evidence matches what
   the posting values most.
3. When several versions are supplied, give each a one-line fit summary
   before recommending one base version. Suggest borrowing a bullet from
   another version only when it is true and relevant.
4. Report which posting requirements no version can support. These are gaps,
   not instructions to add claims.

## Consistency checks across versions

- Same dates, titles, employers and metrics everywhere.
- Same headline numbers (budget, team size, project count) in every version.
- Differences should be in emphasis and order, not in facts.
- Different versions describe the same person: a recruiter at one employer
  may see more than one of them.

## Tip: showing your versions publicly

If you publish an example, use a fictional person and fictional
organizations. Real file names or employer-specific versions reveal where you
applied.
