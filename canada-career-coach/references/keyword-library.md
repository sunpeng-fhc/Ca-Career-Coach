# Keyword Library

Starting banks of terms by role track. They are **seeds, not a verified
list**: confirm each term against the actual postings you are targeting before
relying on it, and add only terms you can truthfully support.

## Track A: IT support and help desk
Typical settings: managed service providers (MSPs), corporate IT teams, health
authorities, school boards, universities and colleges, municipalities.

Terms: Tier 1 / Level 1 support, service desk, ticketing system, ServiceNow,
Jira Service Management, incident management, service requests, SLA,
troubleshooting, Windows 10/11, macOS, Microsoft 365, Teams, Active Directory,
Entra ID (Azure AD), Intune, MFA, password resets, user onboarding and
offboarding, device imaging, VPN, remote support, printers and peripherals,
asset management, knowledge base, escalation, customer service, ITIL.

Coaching note: entry-level postings value hands-on troubleshooting and clear
communication with non-technical users. Home labs, volunteer tech support and
certifications can support terms here, but only for tasks the user actually
performed.

## Track B: Application support
Typical settings: banks and insurers, energy and utilities, software
vendors, health authorities, large corporate IT teams.

Terms: application support, production support, Tier 2 support, incident and
problem management, root cause analysis, change management, ServiceNow, Jira,
SQL queries, log analysis, monitoring tools (such as Splunk or Datadog), APIs,
Postman, ERP and CRM platforms (such as SAP, Salesforce or Dynamics 365), SaaS
administration, user access management, release support, UAT, runbooks,
documentation, SLA, on-call rotation, PowerShell.

Coaching note: this role sits between IT support and business analysis.
Postings look for evidence of investigating issues in a specific application
and explaining them to business users. Name a platform only if the user has
worked in it.

## Track C: Junior web development
Typical settings: digital agencies, technology startups, in-house web teams,
software companies, public-sector digital teams.

Terms: HTML, CSS, JavaScript, TypeScript, React, Next.js, Node.js, Express,
REST APIs, Git, GitHub, responsive design, accessibility (WCAG), cross-browser
testing, Tailwind CSS, Figma handoff, unit testing (such as Jest), CI/CD,
deployment (such as Vercel or Netlify), SQL and NoSQL databases (such as
PostgreSQL or MongoDB), WordPress, SEO basics, Agile, code review.

Coaching note: entry-level postings weigh a portfolio and GitHub link heavily.
School and personal projects count as evidence when labelled as such. List
only frameworks the user has built something with, and be ready to walk
through the code.

## Track D: Cloud and system administration
Typical settings: MSPs, corporate infrastructure teams, cloud consultancies,
software companies, public sector.

Terms: AWS (EC2, S3, IAM, VPC), Microsoft Azure, Microsoft 365
administration, Windows Server, Linux, Active Directory, Group Policy, DNS,
DHCP, TCP/IP, networking basics, virtualization (VMware, Hyper-V), backup and
recovery, patch management, monitoring, PowerShell, Bash, infrastructure as
code (such as Terraform or CloudFormation), security groups, least privilege,
cost optimization, CompTIA (A+, Network+, Security+), AWS and Azure
certifications.

Coaching note: foundation-level certifications show knowledge, not
experience. Many junior cloud postings expect prior support or system
administration work, so report that gap honestly and point to lab work only
where the user built and ran something.

## Track E: Product and operations
Typical settings: technology companies, e-commerce and retail, logistics,
financial services, startups.

Terms: product requirements, roadmap, backlog, prioritization, user research,
user stories, product metrics, KPIs, OKRs, A/B testing, funnel analysis,
customer feedback, launch coordination, cross-functional collaboration,
process improvement, SOPs, operational reporting, vendor management, Jira,
Confluence, Excel, SQL, dashboards, Lean, Six Sigma.

Coaching note: job titles do not travel well between countries or company
sizes. Describe scope (team size, products, decisions owned) rather than
relying on a title, and add one line of context for employers outside Canada.

## Track F: Business and data analysis
Typical settings: banks and insurers, energy and utilities, government
departments, health authorities, consultancies, technology companies.

Terms: requirements gathering, stakeholder interviews, process mapping, BPMN,
current-state and future-state analysis, gap analysis, business case, user
stories, acceptance criteria, UAT, Agile, Scrum, Jira, Confluence, Visio, SQL,
Excel (pivot tables, XLOOKUP), Power BI, Tableau, data cleaning, data quality,
dashboards, KPIs, reporting, IIBA (ECBA, CCBA, CBAP).

Coaching note: analyst postings reward structured problem framing and a clear
link from analysis to a decision. Name tools such as SQL or Power BI only at
the level the user can demonstrate in an interview.

## Common Canadian posting requirements
These are not keywords to add, but they often decide eligibility. Check each
one against the profile and report it plainly:
- Valid driver's licence (for example Class 5 in Alberta) and access to a
  vehicle, common for field IT and site-based roles.
- Criminal record check or police information check, common in health,
  education and government roles.
- Security clearance, such as Reliability Status or Secret.
- English–French bilingualism, required or listed as an asset.
- Physical requirements, such as lifting equipment.

## ATS optimization rules

1. Mirror the posting's wording where the user genuinely has the experience;
   do not paraphrase a specific term away.
2. Place the highest-priority terms in the first three bullets of each
   relevant role.
3. In a skills section, list only tools and methods actually used.
4. Avoid keyword stuffing. Modern systems and human readers both look for
   context.
5. Use a simple layout: standard section headings, no text inside images, and
   no important information in headers, footers or text boxes.
6. Many postings, especially in government, add screening questions. Answer
   them with the same evidence the resume shows, using the posting's wording.
7. Submit in the format the employer requests; if none is stated, check the
   application page, since requirements differ.
